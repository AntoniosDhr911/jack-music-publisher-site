Privacy Policy

Effective date: 2026-09-07. Governing jurisdiction: Lebanon. Controller/operator: Jack Daher.

JACK Music Publisher ("JACK") is a private, internal tool. It is not offered to the public and does not collect personal information from members of the public. This policy describes how JACK handles data belonging to its own operator(s) and to the third-party platform accounts (YouTube, Meta, TikTok) it is authorized to publish to on their behalf.

YouTube API Services

JACK uses the YouTube API Services. By authorizing JACK against a Google account, the operator agrees to be bound by the YouTube Terms of Service. Google's own handling of data is described in the Google Privacy Policy.

JACK requests only the youtube.upload OAuth scope. It stores the resulting OAuth credential locally, on the operator's own machine, in an OS-appropriate per-user application-data location -- never inside this project's own source repository or the release-media workspace it publishes from.

When the operator approves a YouTube upload, JACK sends the selected local video file, thumbnail image, and the release's operator-provided YouTube upload metadata to YouTube for the operator-configured target channel solely to perform that requested upload. The upload metadata consists of the title, description, tags, category id, privacy status, made-for-kids setting, and synthetic-media disclosure selected for that release.

JACK does not durably retain the YouTube API-returned identifier for an uploaded video. That identifier exists only within the narrow upload operation that receives it: it is never returned from that operation, never logged, and never written to JACK's local publication-state record. JACK's durable local duplicate-upload- protection record instead tracks only an identifier-free status (pending, requires manual verification, or complete) for each release. That identifier-free status is JACK's own local operational state, not a retained YouTube API response identifier.

An operator may revoke JACK's Google authorization at any time by running JACK's own youtube disconnect command (which calls Google's documented token-revocation endpoint), or directly at Google Account permissions. Revoking or deleting local data through JACK does not delete any video or content already hosted on YouTube -- that must be done directly in YouTube Studio.

Meta (Facebook/Instagram) Platform data

JACK similarly uses the Meta Graph API to publish to an operator's own Facebook Page and linked Instagram Professional account. Data obtained through Meta's Platform is used solely to perform the publishing actions the operator explicitly requests, and is not sold or shared with third parties. JACK does not currently provide its own local Meta credential-revocation or data-deletion command; an operator can revoke JACK's Meta access directly from their Facebook account's Business Integrations settings, which is the operative deletion/revocation mechanism for Meta data today. This section will be updated to describe a JACK-provided command if and when one exists. Revoking Meta access, however it is done, does not delete any post, Reel, or content already hosted on Facebook or Instagram.

Retention

Local application data is retained only as long as necessary to operate JACK's publishing and duplicate-protection functionality, consistent with each platform's own API terms. For YouTube data, an operator may request deletion of locally stored data via JACK's own youtube delete-data command, which quarantines and attempts to revoke JACK's Google authorization, then removes the local policy-acceptance record, minimizes locally stored YouTube publication-state records, sweeps any abandoned local YouTube media-snapshot data, and cancels any pending YouTube-bearing schedule -- this local cleanup happens regardless of whether Google's remote revocation endpoint confirms the credential is revoked, since a locally quarantined credential is already unusable by JACK either way. JACK does not yet provide an equivalent local deletion command for Meta or TikTok data. For Meta, the current revocation route is described in the Meta section above. JACK's TikTok API integration remains limited to development/Sandbox testing, while production TikTok posting is performed manually through TikTok's normal creator interface; this policy does not claim a JACK-provided TikTok revocation or local data-deletion command.
